# node/: server and configuration page

*[Português](README.md)*

The Stream Deck ESP server in TypeScript (Node 22+ runs `.ts` directly, no build step; `npm run typecheck` checks the types).
It serves the configuration page (`web/`), hands the board its configuration and images and runs the actions when the board reports a tap.

```bash
npm ci
npm start                # port 8765, with mDNS; data in ../data (config.json, token, uploads, cache)
npm run typecheck        # tsc --noEmit
npm test                 # full suite (needs macOS)
npm run test:ci          # portable subset (macOS, Windows, Linux) used by CI
```
Variables: `DECK_PORT`, `DECK_DATA` (config/token/uploads folder), `DECK_CACHE`, `DECK_NOMDNS=1`, `DECK_DRYRUN=1` (prints the commands instead of running them), `DECK_NOPLUGINS=1`, `DECK_PLUGINS_DIR`, `DECK_PLUGIN_PORT` (3907), `DECK_PLUGIN_LOG=1`.
To test without touching your configuration: `DECK_DATA=$(mktemp -d) DECK_PORT=8799 DECK_NOMDNS=1 DECK_DRYRUN=1 npm start`.

## Modules (`src/`)
| File | What it does |
|---|---|
| `server.ts`, `main.ts` | HTTP (page on localhost, board API with token), pairing, mDNS, periodic tasks (widgets, state, resources) |
| `config.ts`, `settings.ts` | pages/buttons (`config.json`), grid and font (`settings.json`), geometry from the screen's physical size |
| `actions.ts`, `netactions.ts` | actions (app, url, hotkey, text, media, sequence, page, webhook, Home Assistant, MQTT) and validation |
| `render.ts`, `fit.ts`, `resample.ts`, `anim.ts` | button images (RGB565), text, resampling, animated GIFs |
| `widgets.ts`, `nowplaying.ts`, `weather.ts`, `resources.ts`, `slider.ts`, `state.ts` | clock, now playing, weather, resource monitor, sliders, buttons with state |
| `icones.ts` | local icon library (`assets/icones/`, generated by `tools/gerar-icones.mjs`) |
| `backup.ts` | export/import the configuration |
| `standalone.ts`, `sa-profile.ts` | standalone mode (profile sent to the board) |
| `usb.ts`, `usb-port.ts` | the board's cable connection (HTTP over serial) |
| `plugins.ts`, `plugin-protocol.ts`, `plugin-install.ts` | plugin host (`*.deckplugin` format; compatibility with Ulanzi Studio plugins) |
| `focus.ts`, `apps.ts` | page switching by focused app, installed-app list |
| `platform/{mac,win,linux}.ts` | **everything system-specific** (open app, shortcuts, media, focused app, volume): never call `open`/`osascript`/`xdotool` outside them |
| `i18n.ts`, `locales/en.ts` | languages (the Portuguese text is the key) |

## Plugins
The host is `src/plugins.ts`; protocol in `../docs/en/PLUGIN-PROTOCOL.md`, guide in `../docs/en/CREATE-PLUGIN.md`, SDK in `../sdk/`. Installed plugins live in `node/plugins/` (ignored by git) and **run code with your user's permissions**.
Ulanzi Studio plugins (SDK 2.1.2) are supported only for compatibility (import, protocol translation in `plugin-protocol.ts`); the project depends on neither the Ulanzi SDK nor its protocol.
Host security: WebSocket on 127.0.0.1 only; web pages only with an `Origin` equal to the server's; plugin files served only from inside its folder and never `config.json`/`devices.json`/`*.pem`/`package*.json`; the "plugin" action is only valid with an existing plugin and action.
Caution: two hosts at the same time (Ulanzi Studio and this one) can conflict on plugins with an exclusive resource (fixed ports, RPC).

## Automatic page switching by focused app (`src/focus.ts`)
A page can be linked to apps; when one of them comes to the front, the board shows that page, and when you move to an app with no link it goes back to the previous page. It only acts when the focused app **changes**; Dock, Spotlight etc. do not count. The focused app comes from `platform.front()` (macOS: `lsappinfo`, no extra permission; Windows: PowerShell; Linux: `xdotool`). Stored in `config.json` (`pages[].apps`, `autoswitch:false` when turned off).

## Tests (`test/`)
Each file is independent and starts a temporary server instance on its own port (88xx), with no mDNS and without touching your data. The main ones: `plugins.ts`, `sdk.ts`, `deck-plugins.ts`, `i18n.ts` (page keys x dictionary), `focus.ts`, `settings.ts`, `stride.ts`, `tiles.ts`, `anim.ts`, `platform.ts` (commands generated for the three systems), `usb.ts`, `slider.ts`, `netactions.ts`, `widgets.ts`, `standalone.ts`, `backup.ts`, `nowplaying.ts`, `state.ts`, `hold.ts`.
Real media validation: `linux-media.ts` (with `test/linux/executar.sh` or `bash test/linux/rodar-docker.sh`) and `windows-media.ts` (PowerShell); see `../docs/en/PLATFORMS.md`.
